## 3. 关键约束：为什么版本目录必须整体同层移动

版本之间存在**硬编码相对路径依赖**（已逐条核对）：

| 位置 | 依赖 |
|---|---|
| `v4_20260718/config.py`、`v3_20260710/config.py` | `_dir.parent / "v2_20260525" / "config.py"` —— 依赖 v2 与其同级 |
| `v2_20260525/src/{cost_model,preprocessing}.py` | `Path(__file__).parent.parent.parent / "shared"` —— 依赖 `shared/` 与版本目录同级 |
| `v2_20260525/validate_v2.py`、`v2/config.py` | `parent.parent / "shared"`、`SHARED_DIR = BASE_DIR / "shared"` |
| `v1_20260525/config.py` | `BASE_DIR = parent.parent`，`OUTPUT_DIR = BASE_DIR / "output"` |

由于本次是**整批同层下沉**（只换父目录名、不改变层级深度），上述相对关系全部保持成立；
`shared/` 一并移入 `archive/历史版本/` 是必要条件 —— 留它在根目录会立刻让 v2 的 `sys.path` 断链。

副作用（已知，低风险）：v1 的默认输出目录由「仓库根 `output/`」变为 `archive/历史版本/output/`
（import 时 `mkdir(parents=True, exist_ok=True)` 自动创建，不报错）。v1 当前无实际运行需求。
