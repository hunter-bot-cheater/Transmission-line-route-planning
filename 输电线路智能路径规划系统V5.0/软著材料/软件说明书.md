## 第 1 章 软件概述

### 1.1 软件名称与版本

- 软件全称：输电线路智能路径规划系统
- 软件简称：输电线 AI 规划系统（可填可不填）
- 版本号：V5.0
- 开发完成日期：待著作权人确认
- 首次发表日期：待著作权人确认（如未发表，按登记系统规则填写）

### 1.2 软件开发背景

输电线路选线（路径规划）是电力工程前期的关键环节。传统方法依赖人工经验与
A\* / Dijkstra 等经典最短路径搜索，在复杂山区难以兼顾「建设代价低」与「路径形态贴合
工程实际走廊」两个目标。本软件在前期版本基础上，加入 VIN-Grad 与 PPO 路径生成流程，并保留
A\* 基线；提供真实线路时，可按空间偏差与长度误差对结果作对照，使规划结果可被
量化、可被独立复算验证。

### 1.3 软件用途

本软件面向电力规划、地理信息、工程勘察等领域，输入数字高程模型（DEM）、地形因子与
OpenStreetMap（OSM）矢量数据，按固定站点/线路接入点任务生成走廊筛查路线，并给出
路径与参考输电线路之间的几何相似度用于结果对照：双向偏移分布、容差带覆盖率、端点偏差、抽样形状距离、缓冲区重叠率和独立长度差。覆盖容差仅描述空间贴合，不输出工程达标结论。
输入真实站点前须核实其站端接入坐标；本软件不自动选址或生成站端接入间隔。输出是前期候选筛查结果，不能代替环境调查、电气设计和工程审查。

### 1.4 软件总体结构

登记范围内的软件包由 15 个 Python 文件组成（含包入口文件），按职责分层：

| 模块 | 职责 |
| --- | --- |
| `config.py` | 全局配置：第三方库导入、常量、确定性随机种子 |
| `geometry.py` | 经纬度↔栅格坐标转换、Haversine 距离、路径长度 |
| `io_export.py` | 规划路径导出为 SHP / GeoJSON |
| `data.py` | DEM 读取、地形因子计算（坡度/曲率/TPI/粗糙度等）、山体阴影 |
| `osm.py` | OSM 矢量数据栅格化、距离带/建筑密度/用地编码/植被高度波段 |
| `corridor.py` | 旧版离线工具：构建既有线路距离场、方向场和区域密度；当前 CLI 未接入 |
| `cost.py` | 26 维特征栈、可选 CostUNet、地形及 OSM 建筑密度路线代价 |
| `methods.py` | 三方法：VIN-Grad（值迭代网络+梯度追踪）、PPO、A\* |
| `stations.py` | 站点台账与站间任务 CSV 校验、任务端点解析 |
| `smoothing.py` | 路径平滑、硬约束吸附、高程采样 |
| `metrics.py` | 双向空间相似度、覆盖率、端点/形状距离、缓冲区重叠和长度差 |
| `visualization.py` | 多算法对比图、价值图、指标柱状图 |
| `cli.py` | 命令行入口与多走廊批量编排 |
| `__init__.py` / `__main__.py` | 包初始化、版本号、`python -m` 入口 |

说明：模块数量按当前 `transmission_path_planner/` 目录中的 Python 文件统计。项目目录中的实验脚本、缓存和历史版本不属于本次源代码鉴别材料范围。

## 第 2 章 运行环境

### 2.1 硬件环境

- CPU：满足 Python、栅格地理数据处理及路径搜索的运行需求
- 内存、GPU、磁盘：随 DEM 尺寸、算法选项、依赖和缓存数据量变化；请按实际部署环境填写，不以估算值代替实测结果

### 2.2 软件环境

- 操作系统：Windows 或 Linux
- Python：以 `requirements.txt` 所列依赖可安装和运行的版本为准
- 关键第三方库：

| 库 | 用途 | 是否必需 |
| --- | --- | --- |
| numpy / scipy / pandas | 数值计算 | 依赖清单所列 |
| shapely / rasterio / geopandas | 矢量/栅格地理处理 | 部分模块提供降级路径 |
| matplotlib | 结果可视化 | 运行入口依赖 |
| torch | VIN-Grad / PPO 深度学习 | 缺失时跳过 VIN-Grad 与 PPO，保留 A\* |
| osmnx | OSM 在线下载 | 可选（可用缓存 .pkl 替代） |

> 部分数据读取逻辑在 `rasterio/geopandas` 缺失时尝试回退 `tifffile + 简化栅格化`；
> `torch` 缺失时仅 `A*` 基线可运行；`osmnx` 缺失时使用已下载缓存。

## 第 3 章 安装与部署

### 3.1 安装依赖

```bash
cd 输电线路智能路径规划系统V5.0
pip install -r requirements.txt
```

### 3.2 数据准备

- **DEM**：GeoTIFF 格式数字高程模型（如 SRTM 30m）。
- **站点台账与规划任务**：`examples/stations_template.csv`、`examples/route_tasks_template.csv`；用核实过的站端接入点坐标填写副本。可选录入站端地面高程、测量来源和垂直基准。历史评估线路端点不可直接当作站点。
- **真实线路（选路后可选对照）**：Shapefile / CSV，含真实输电线几何。
- **OSM 数据**：使用项目配置可读取的缓存/矢量数据；建筑足迹和建筑密度仅用于初筛，不能代表完整居民点或敏感目标清单。
- **自定义约束**：可将有来源记录的禁入面或偏好面制成 WGS84 GeoJSON，多边形要素按属性设置硬约束或软代价；需人工核对数据来源、日期和范围。

### 3.3 一键运行（Windows）

`run_real_tw.bat` 从软件目录运行，读取目录内的 `data/taiwan_dem_35m.tif`，并读取上一级工作区 `data/real_cases_tw/` 中的测试 CSV 与真实线路 SHP。软件目录单独复制部署时，应按实际位置修改批处理脚本中的 DEM、测试数据和输出路径。

## 第 4 章 操作说明

### 4.1 命令行主流程

```bash
python -m transmission_path_planner \
    --dem ./data/taiwan_dem_35m.tif \
    --stations-csv ./examples/stations.csv \
    --route-tasks-csv ./examples/route_tasks.csv \
    --constraint-geojson ./data/verified_constraints.geojson \
    --out-dir ./results/station_routes --no-ppp
```

站间任务模式检查站点 ID、坐标和任务引用关系；端点不会自动吸附到邻近栅格。没有站点台账时，可继续用 `--start/--end` 做算法调试，但这不构成站间规划任务。

规划入口不提供待规划线路引导参数。真实线若一并提供，会在 A*、VIN-Grad、PPO 候选生成和最终选路之后才读取，仅用于计算事后空间偏差和长度误差；规划阶段不会用它构造代价、放宽硬约束、筛选重试或决定路线。最终路线按固定优先级及硬约束筛选（A* 可行时优先，否则依 VIN-Grad、PPO 顺序回退）；没有真实线时仍会导出最终路线，但不生成参考误差指标。要把实验称为严格无泄漏，还须核验训练集和预训练权重未包含测试线路。

命令行参数应以 `python -m transmission_path_planner --help` 显示内容为准。当前入口使用 `--out-dir` 和 `--real-cases-csv` 等参数；不提供 `--out`、`--vin`、`--ppo`、`--guide-mode`、`--corridor-w` 或 `--real-attract` 选项。A* 流程始终运行；检测到 PyTorch 后运行 VIN-Grad（可用 `--no-vin` 跳过），并在未指定 `--no-ppp` 时尝试 PPO。VIN 或 PPO 显存不足时只跳过对应神经方法并继续 A*；起终点必须落入完整硬约束掩膜的可通行像元，程序不静默挪动端点。真实线路只用于选路之后的事后评估，参考 SHP 必须含有效 CRS、有效经纬度和正长度；`--real-shp` 只接受单任务且恰含一个 LineString 要素的目标线路，`--real-dir` 则按任务匹配文件并支持由多个线段组成的目标线路。损坏或 CRS 缺失的逐任务参考文件记为未评估，不中断路线规划；`--real-cases-csv` 遇到缺列、坏行或非法坐标时拒绝整份输入，启用逐任务参考线匹配时也会拒绝文件名净化后冲突的任务名。站点 CSV、`--start/--end`、`--real-cases-csv` 和 `--real-cases` 只能选择一种任务来源，避免冲突参数被静默忽略；真实用例 CSV 默认从同目录找参考线路，显式 `--real-dir` 时使用所指定目录。输出标记 `route_similarity_version=2`；单线端点/形状指标在多线段参考几何时留空，长度差与空间距离分开展示。

### 4.2 主要功能模块与操作

| 步骤 | 功能 | 对应模块 | 说明 |
| --- | --- | --- | --- |
| 1 | 任务与数据载入 | `stations.py` / `data.py` / `osm.py` | 校验站点与任务 CSV，读取 DEM、计算地形因子并栅格化 OSM |
| 2 | 代价与障碍构建 | `cost.py` | 默认构造可解释的地形和建筑密度代价；建筑足迹作硬障碍；CostUNet 仅通过 `--use-costunet` 显式启用 |
| 3 | 路径规划 | `methods.py` | 依次运行可用的 VIN-Grad、PPO 和 A\* 流程生成候选路径 |
| 4 | 路径平滑 | `smoothing.py` | RDP 抽稀、硬约束吸附；逐段验证平滑线路，穿越禁行像元则回退原始可行路径 |
| 5 | 空间相似度对照 | `metrics.py` | 约 20 米弧长双向采样，报告偏移分布、容差带覆盖 F1、端点/形状、缓冲区 IoU 和独立长度差 |
| 6 | 结果导出 | `io_export.py` / `metrics.py` | 输出 SHP / GeoJSON、指标 JSON 和 DEM 高程纵断面 CSV |
| 7 | 可视化 | `visualization.py` | 生成对比图、价值图、指标柱状图 |

### 4.3 关键参数说明

| 参数 | 含义 | 推荐值 |
| --- | --- | --- |
| `--no-ppp` | 跳过 PPO 方法 | 默认不跳过 |
| `--no-vin` | 跳过 VIN-Grad，仍运行 A* 与启用的 PPO | 显存不足或只需基线时使用 |
| `--real-shp` | 单任务目标线路的事后对照文件，必须有 CRS 且恰含一个 LineString 要素 | 多任务改用按路线匹配的 `--real-dir`；支持目标线路分段存储 |
| `--stations-csv` / `--route-tasks-csv` | 站点台账与站间任务 | 固定站点规划时同时提供 |
| `--constraint-geojson` | 用户提供的 WGS84 Polygon/MultiPolygon 约束层；属性含 `mode`、`source`，软代价还需 `weight` | 按数据来源及适用规则设置 |
| `stations.csv` 可选高程列 | `ground_elevation_m`、`ground_elevation_source`、`vertical_datum`；仅在来源齐全且两端基准一致时报告实测高差 | 无核验测量时留空 |
| `--settlement-weight` | OSM 建筑密度代理的软代价权重 | 默认 2.0，须按场景核验 |
| `--building-clearance-m` | OSM 建筑轮廓外扩的筛查距离 | 默认 0 m，不代表法定净距 |
| `--max-ground-grade` | DEM 相邻像元地面高差率筛查阈值 | 默认关闭；不是导线或塔位设计限值 |
| `--max-surface-slope-deg` / `--max-terrain-elevation-m` | 可选地表坡度/海拔筛查阈值 | 默认关闭；需由项目方给定并核验 |
| `--use-costunet` | 将兼容 CostUNet 预测作为软先验 | 默认关闭；模型训练数据仍需审计 |
| `--out-dir` | 指定结果输出目录 | 未指定时使用配置目录 |

## 第 5 章 软件功能与技术特点

### 5.1 核心功能

1. **固定站点间走廊筛查**：通过站点台账和任务表绑定线路两端；默认路径代价使用 DEM 地形因子和 OSM 建筑密度，建筑足迹按配置作为硬障碍，也可加载带来源记录的用户约束面。
2. **多方法候选路径**：运行可用的 VIN-Grad、PPO、A\* 流程生成候选路径；A\* 硬约束合规时优先作为最终路线，否则按 VIN-Grad、PPO 的顺序选择首个合规候选。
3. **参考线路对照**：提供参考线路时，写出双向偏移统计、容差带覆盖 F1、单线端点与形状距离、缓冲区 IoU 和独立长度差；结果依赖参考几何本身。
4. **独立参考评估**：目标真实线只在最终路线选定后读取，计算空间偏差和长度误差，不作为规划方向先验。
5. **随机种子设置**：程序固定部分随机种子并设置 cuDNN 选项；不能据此保证不同设备和依赖版本间结果完全一致。
6. **纵断面记录**：对最终路线采样 DEM，输出站端高程、站间高差、累计上升/下降、最大采样地面坡度及逐点纵断面 CSV；这些指标不等同于架空导线净空计算。
7. **批量与可视化**：支持多任务批量运行，输出路线图、指标图表与矢量结果。

### 5.2 技术特点

- **多方法对照**：程序依次生成 VIN-Grad、PPO 与 A* 候选；A* 合规时优先选择，否则按 VIN-Grad、PPO 固定优先级回退到合规 AI 路径。真实线误差只在选路后计算，不参与候选或最终路线选择。
- **度量面向工程实际**：提供参考线路时，同时计算长度与空间偏差指标。
- **几何对照**：在本地米制投影下按弧长双向采样，分开报告偏移分布和线路覆盖；端点、离散 Fréchet 与缓冲区 IoU 作为辅助指标，长度差单独记录。
- **模块化组织**：登记范围内 15 个 Python 文件按职责拆分，便于阅读和维护。

## 第 7 章 软件维护与注意事项

1. **随机性**：`config.py` 设置了随机种子；结果仍可能受设备、库版本和算法路径影响。
2. **降级运行**：缺少 `torch`、显存不足或显式使用 `--no-vin` 时跳过 VIN-Grad；缺少 `torch` 或显式使用 `--no-ppp` 时跳过 PPO，保留 A* 基线。VIN 显存不足不会中断 A* 和真实线路事后评估。
3. **端点与禁区**：起终点映射到 DEM 栅格后必须位于 DEM 范围内并通过完整硬约束掩膜；程序不会静默移动接入点，也不会把端点格重新开放。
4. **数据范围**：真实线路只用于规划后的事后评估，不作为规划引导。所有参考 SHP 必须含 CRS；`--real-shp` 仅接受单任务且恰含一个 LineString 要素的文件；`--real-dir` 按任务匹配文件，可由多个 LineString 或 MultiLineString 线段组成。损坏的逐任务参考文件不阻断规划，但会记为未评估。
5. **数据边界**：OSM 建筑覆盖不完整，建筑密度只是建成区代理；本项目没有可用的官方保护区/生态红线、人口及敏感目标台账，也没有塔位、档距、弧垂与净空设计模型。请勿将筛查结果表述为“已满足工程约束”或“已完成合规避让”。
6. **批次完整性**：`run_summary.json` 的 `complete` 仅在所有用例都生成可行路线及必需路线文件时为真；失败用例和无可行路线用例会分别列出。汇总图表等可选产物不在此字段范围内。误差复测应确认 `real_evaluation_by_case` 的状态为 `comparison_completed`，并核对实际评估方法列表；仅加载参考线不代表完成误差计算。
7. **登记范围**：本说明书和《源程序.txt》对应 `transmission_path_planner/` 目录中的登记源代码，不代表仓库里的实验数据、旧版本或其他脚本均已纳入。
