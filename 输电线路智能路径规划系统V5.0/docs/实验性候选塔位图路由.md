# 实验性候选塔位图路由

`transmission_path_planner.experimental_tower_graph.tower_graph_route` 是未接入 CLI 的站间线路实验器。它将可设塔位置作为图节点，将满足给定水平档距范围、且直线段 supercover 不触碰硬禁区的跨距作为边；跨距阻力沿现有栅格成本面按像元常值精确积分。可选塔位成本单独计入节点。邻边在搜索首次展开节点时按空间索引惰性生成并缓存，不会预先构造整张候选图。零转角惩罚时使用节点状态；启用转角惩罚时使用 `(前一塔位, 当前塔位)` 状态累计转角成本。两种状态都使用 A*，启发下界为全图最小有效像元阻力乘当前节点到终点的欧氏距离：每米跨距阻力不低于该最小值，剩余跨距总长不小于欧氏距离，且塔位与转角项非负，因此该估计不会高估剩余目标值。若最小像元阻力为零，启发退化为零，搜索等价于 Dijkstra。

## 适用边界

- 站点是固定端点，不要求通过塔位掩膜。端点落在硬禁区或栅格外时返回无路，不吸附。
- 候选塔位从有效栅格按 `candidate_stride` 稀疏采样，采样格点锚定栅格原点；稀疏采样可能漏掉可行塔位，结果只代表该候选图。`tower_allowed_mask` 控制能否立塔，`traversable_mask` 控制线路跨距能否通过。禁设塔区因此不必阻断导线跨越。
- `min_span_m`、`max_span_m` 和候选间隔必须由调用方提供。测试中的数值只验证算法行为，不代表任何电压等级或设计规范。
- `cost_raster` 表示每米线路阻力，`tower_cost_raster` 的值必须用可相加的目标单位标定；缺少实际造价和地权数据时，它只能表达相对惩罚，不能标作货币成本。`turn_penalty_weight` 是无量纲倍率。
- A* 对当前候选图上的目标值做精确搜索；候选塔位仍由 `candidate_stride` 稀疏采样，惰性建图和 A* 不会补回未采样的节点，也不代表对连续地形问题的全局最优。
- 起点和终点是固定站端，其塔位成本不参与目标，也不会因端点上的塔位成本值触发校验；中间可设塔位置的成本必须有限且非负。
- 这是二维线路走廊筛查原型。它尚未使用 DEM 纵断面、塔高、导线弧垂、风偏、净空、荷载、跨越许可或站点实测高程，不能输出工程可行结论。
- 转角代价依赖前后相邻塔位；搜索禁止沿刚走过的跨距立即折返，但状态不记录完整访问集合，因此仍没有全局简单路径保证。极端转角权重下可能形成更长环路，使用方必须检查并清除重复塔位。转角项应保持实验性，且不能单独视作工程塔位优化结论。

## 合成检查

在均匀成本栅格中，35 米像元、端点 `(5, 1)` 到 `(5, 37)`、水平档距 175–350 米时，返回路线的每一段均在范围内，反向任务返回同一几何。禁设塔列不会成为塔位节点，但线路可以从其上方跨过；把候选塔位成本集中加到一侧后，路径会改用另一侧。将整列设为线路硬禁区后则返回无路。测试还覆盖保守 supercover、立即折返限制、采样导致的可达性差异、跨距上下边界、零成本启发退化，以及在小型显式候选图上将 A* 目标值与独立全图 Dijkstra 对照。自动化检查见 `tests/test_experimental_tower_graph.py`。

### 搜索开销基准

零转角分支只记录当前节点；对非负跨距成本和塔位成本，节点状态与有向边状态的最优目标值等价。图搜索现在只展开被访问节点的局部可行跨距，已检查边只计算一次；只有启用转角成本时才保存按向边成本。A* 使用可采纳启发下界，最低栅格阻力为零时自然退化为 Dijkstra。

上一轮预建完整图比较曾记录 64×64 上有向边状态搜索 2.529 秒、零转角节点态 Dijkstra 0.315 秒；那次运行没有保存逐次样本和脚本，不作为可复现的当前性能结论。本轮用 `tools/benchmark_tower_graph.py` 测量惰性邻接 A*：全可通行、均匀单位成本，像元 35 米、采样间隔 2、档距 175–350 米，端点为栅格对角线两端；每个尺寸先预热一次，再测量三次并取中位数。可复现命令为：

```powershell
& 'D:\python\python.exe' -B tools\benchmark_tower_graph.py `
  --sizes 64 128 256 512 --repeats 3 `
  --output outputs\tower_graph_benchmark_20261024.json
```

Windows 11、Python 3.13.6、NumPy 2.3.4 环境的复测中位数为：64×64 **0.0188 秒**、128×128 **0.0377 秒**、256×256 **0.0770 秒**、512×512 **0.2268 秒**；路线节点数分别为 14、30、55、93。结果文件保存逐次样本和运行环境。该计时只包含路由函数调用，不含 Python 导入；它只描述合成开阔面上的单任务运行时间，不含真实 DEM 和约束层，不代表真实路线精度、覆盖度或工程可行性，也不保证不同机器的绝对耗时。

开源的 [PowerPlanner](https://github.com/NinaWie/PowerPlanner) 和 [LION 研究框架](https://arxiv.org/abs/2101.03388)采用候选塔位节点及可行档距边，可作为下一步工程模型的结构参照。当前原型只实现了其中的图搜索骨架；接入真实任务前需要有可追溯的线路电压、导线/地线、塔型、档距、弧垂净空和塔位约束数据。
