# 居民区软惩罚反事实实验预注册

## 问题与假设

本实验检验现有 OSM 建筑密度、住宅用地和城镇用地代理加入路线软代价后，候选路线是否更少穿过已映射居民区代理。对照为 `settlement_weight=0`，处理组为 `settlement_weight=2`。其余规划输入、代价参数和搜索配置保持一致。

这是地图代理成本的敏感性实验，不假设现有 OSM 覆盖完整，也不把代理值解释为人口数量或真实居民暴露。

## 固定条件

- 12 组输入端点来自 `D:\大创\data\real_cases_tw\real_cases.csv`；它们是历史线路端点，属于固定端点诊断，不是独立变电站数据验证。
- 使用项目内 35 米 DEM、同一组 OSM 缓存，以及农业农村部灾害矢量瓦片包。正式运行器在启动前登记全部输入文件大小和 SHA-256，并校验瓦片包的 `tiles.sha256`。
- 两臂都显式固定地形坡度权重 0.75、粗糙度权重 0.25、脊线权重 0.1、土地覆盖权重 0、地面坡度边权重 1、转弯权重 0、灾害软权重 1、建筑足迹净空 0 米、A* 启发权重 1，以及最大网格边长 4096。
- 两臂都关闭 VIN、PPO 和 CostUNet，不使用额外 GeoJSON 约束。
- 已映射建筑足迹的硬掩膜在两臂中相同；本实验不比较有无建筑硬避让。

## 隔离与冻结

运行器先记录 Git 提交、规划代码、端点 CSV、DEM、OSM 缓存、官方灾害瓦片包、参数和运行环境，然后顺序运行两个权重组。`reference_quarantine` 在运行前为空，并通过 `--real-dir` 显式传入；参考线评分必须是 `reference_missing`。所有候选与输入哈希写入清单且复核通过后，评分工具才允许读取历史线 Shapefile。事后结果写入独立 `posthoc_settlement` 目录，不修改候选，也不据分数调权或选路线。

## 预先确定的报告指标

主代理指标是 CLI 导出的 `mapped_settlement_proxy_mean`：最终线触碰像元中，建筑密度、住宅掩膜和城镇用地代理的最大值均值，采用 all-touched 栅格化。该指标不按线长加权，必须和路线长度及逐层覆盖状态一起解读。若任一必要图层不可用或两臂覆盖状态不同，不计算配对总体中位数，并列出被排除案例。

历史线只在候选冻结后进行描述性比较，逐案报告双向距离 P95、双向均值、采样 Hausdorff、F1@100 米和长度差。结果不用于选参、挑路线或声称工程可行。

## 解释边界

算法求解的是给定离散栅格代价和硬掩膜下的路径筛查问题。实验不能补出输电走廊规划中缺少的站址接入点、杆塔落点、档距、导线弧垂净空、跨越许可或真实人口覆盖信息，也不能证明规划线能复现历史建设决策。
