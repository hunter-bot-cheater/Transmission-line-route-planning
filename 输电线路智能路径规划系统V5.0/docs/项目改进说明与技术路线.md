# 项目改进说明与技术路线

本文根据《大创计划书_修改版.docx》梳理原计划与当前 V5.0 代码的差异，并记录本轮移除目标线路引导、强化事后独立评估的改动。计划书是项目背景材料；本文不把尚未实现的计划内容描述为已完成成果。

## 1. 原计划与当前实现

计划书提出三阶段主线：先建立纯机器学习路径规划基线，再与 WOA/GWO/SSA、IPSO-SA 等方法比较，最后把学习算法与群体搜索融合，并接入“扫描—地图更新—路径优化”的动态流程。

当前 V5.0 登记范围主要解决山区输电线路静态选线，包含 26 维代价特征、VIN-Grad、PPO 和 A*。旧版文稿曾引用 50/100 条线路批量实验，但相关脚本和报告不在当前仓库，无法在此复核，不作为本轮效果证据。核心包里尚未找到无人机覆盖扫描、观测后更新地图、动态重规划的可运行模块；计划书列出的 WOA/GWO/SSA 对照和在线融合也没有体现在这个 CLI 的主流程中。开发工作区曾另有 `V5_final/simulation/` 演示原型，但它不属于本仓库；原型覆盖合成地形扫描和已知区域 Dijkstra 重规划，不读取真实 DEM 或无人机传感数据，也没有接入 V5.0 CLI。该外部原型只能称作计划验证原型，不能写成真实地图上的在线系统。

## 2. 目标线路引导的痛点与移除

将待规划线路的真实线作为“引导线”不符合实际部署条件，也会把测试答案提前交给规划器。旧入口曾按真实线增加走廊代价、调整附近约束，并用误差挑选 VIN/PPO 重试和最终路线；没有真实线时最终路线规则也不清晰。既然新建线路规划通常拿不到目标线路几何，这些功能现已从当前模块化 CLI 和 VIN/PPO 路径函数中移除。

当前规划按以下顺序执行：

1. 默认仅根据站点、DEM、建筑和显式配置的约束运行确定性 A*；可选加权 A* 通过启发函数权重改变搜索次序。
2. 最终路线只从启发式搜索结果中选择。VIN/PPO 只有在显式开启诊断时运行，且不参与最终选择或 A* 失败后的回退。
3. 完成选路之后才载入真实线路，并计算各候选与最终路线的误差。误差不参与代价、硬约束、随机重试或最终选路。

真实线路可通过 `--real-cases-csv`、`--real-shp` 或 `--real-dir` 提供，但规划选路完成前不会加载其几何。选路函数只接收方法路径与硬约束检查结果，不接收参考误差。`selection_rule` 写入指标 JSON 与最终路线 GeoJSON。严格的模型泛化结论还需核验训练数据和预训练权重未包含测试线路，并保存线路族或地理分区划分清单。

VIN 的值迭代实现仍保留作可选诊断：输入使用 A* 同源的像元代价和硬掩膜，8 邻域边按行列实际米距加权，屏蔽禁行邻格及对角切角，并统一目标状态值为零。VIN 是学习到的近似值场，未纳入 A* 使用的地面坡度边代价，不作为默认规划器。

早期仅用 TW173 测试加权 A*（启发权重 1.5）时未观察到明显改善。后续在同一 DEM、代价面与 12 条线路上完整对照后，权重 1.5 的 F1@100m 均值为 3.48%（权重 1.0 为 3.29%），9 条改善、1 条持平、2 条变差；平均搜索时间减少约 17%，平均路径代价增加约 0.58%。据此将 1.5 用作默认走廊筛查策略，同时保留 1.0 作为当前代价面最优路线选项。该变化仍未解决贴合目标：最高 F1@100m 为 9.67%，0/12 达到 95%。

随后检查发现，加权 A* 的启发式搜索在交换起终点时可能选择不同的等价分支。现已将搜索方向规范化，并在优先级相同时优先扩展启发值较小的节点；路径输出再恢复任务方向。以相同 20 米 DEM、OSM 缓存和 12 条线路配对重跑后，F1@100m 均值从 3.48% 升至 3.75%，中位数维持 2.89%；变化集中于 TW311（提升 3.17 个百分点），其余 11 条变化均小于 0.05 个百分点。0/12 达到 95%，因此该修正仅改善搜索方向的一致性，没有实质解决与历史线路的贴合问题。

## 3. 当前证据能支持什么结论

旧版项目文稿曾写有以下历史数字，但当前仓库不含对应的 `batch50/`、输入数据或评估报告，无法独立复核：

- 50 条测试线：候选池 47/50，确定性自动选优约 25/50。
- 扩展到 100 条后：候选池 80/100，确定性长度规则选优 42/100。

这些数字仅是未复核的历史文稿记录，不作为当前版本的测试结果。即使历史记录准确，候选池达标也只是“至少有一个候选事后贴近真实线”的上限证据，不等于系统能在规划前自动识别该候选。长度规则还使用测试 CSV 的 `length_km` 先验，不能直接代表纯起终点场景。50 条与 100 条记录的误差阈值、候选集构成和选优规则可能有差异；还须核验 CostUNet 等模型权重的训练线路清单，才能讨论严格泛化。

## 4. 对引导线依赖的建议

真实线路的走向通常还受征地、既有通道、保护区、施工便道、塔位间距、跨越许可等未完整编码因素影响。仅凭起终点和 DEM/OSM，不能保证复原某一条已建线路。建议按以下顺序解决：

1. **把真值从规划接口移出。** 规划只输入起终点、DEM、合法禁建区、保护/避让规则及确实可获得的工程约束。真实线只在独立评估步骤加载。
2. **将隐性“引导线”换成可审计约束。** 需要工程人员给方向信息时，输入宽走廊面、必经点、禁入面或塔位范围，并在结果中记录其来源和权重。不要把测试线路的精确坐标伪装成普通先验。
3. **线路几何只用于数据泄漏审计。** 本机 1,795 条输电线路图层与当前 12 条评测线同源：12/12 组端点均唯一匹配，偏差小于 0.1 米。该图层不进入规划器，也不作为训练/选路先验；直接检索只能复现输入真值，不能证明规划精度。后续严谨评测应使用按线路族或地理区域留出的独立测试集，并审计模型权重训练来源。
4. **把输出定位为候选方案集。** 用多组可解释的代价权重和转向惩罚生成互相有差异的候选，再按硬约束、建设代价、绕行率、跨越风险、曲率和塔位可行性排序，提供工程师复核。旧版文稿中的 50/100 条实验数字尚未从原始材料复核，CLI 的多参数候选池也尚未集成到当前入口。
5. **把动态扫描原型逐步接入真实数据。** 开发工作区旧版 `V5_final/simulation/` 曾有合成地图、扫描覆盖度、观测掩码和周期性 Dijkstra 重规划原型，但文件未纳入当前仓库。后续需在可交付代码中接入真实 DEM/传感器增量，记录每轮代价图变化，并在相同预算下比较固定 A*、重规划 A*、PPO 与融合策略。训练/测试按地图或区域隔离，并报告多随机种子的均值和波动，才能验证动态融合增益。

### 4.1 将规划对象改为站点间线路任务

用户提出的站点问题成立。工程任务连接的是已确定的变电站或线路接入点；只给任意两个经纬度无法表达线路归属、电压等级和站端进出线位置。此前 `real_cases.csv` 的端点来自评估线路几何首末点，现有工作区也没有经过核验的变电站台账，不能把这些测试点冒充站点。新的 `stations.csv` 与 `route_tasks.csv` 负责把站点身份、接入坐标和待规划任务绑定起来。站点选址仍与固定站点间的走廊规划分开处理。

站点间高差、沿线地形、居民建成区以及禁入区域确实会影响候选路线。当前实现对可用数据采取分层处理：

- 搜索将站端接入点映射到其所在 DEM 像元；输出路线首尾恢复用户提供的精确坐标，并记录到像元中心的距离。若接入点所在像元是 DEM 空值、已映射建筑或启用的禁区，规划报错，不静默移动到最近可通行像元。
- DEM 表面坡度、粗糙度和相邻像元高差参与路线代价；显式配置地面高差上限时，会在平滑、端点恢复之后再次检查所有候选路线。输出端点 DEM 高程差、累计升降、最大采样地面坡度和 `elevation_profile.csv`。这些是地形筛查指标，不是导线弧垂/净空或塔位可行性计算。
- 站点台账可选提供测量地面高程、来源和垂直基准。仅当两端测量与来源齐全、基准一致时才单独报告实测高差；它不会覆盖 DEM 值或自动成为路线阈值。
- OSM 建筑轮廓作为当前可用的硬障碍；平滑建筑密度与住宅用地标记合成建成区代理软代价。其他 OSM 图层不参与本轮规则代价；结果记录图层缓存和观测范围状态。OSM 覆盖不完整，也无法区分完整住宅、人口和敏感目标；默认避让只覆盖数据中映射的建筑足迹。本轮评测未启用 CostUNet，避免模型训练数据中的线路信息影响规划。
- 可通过 `--constraint-geojson` 加载带来源记录的 WGS84 Polygon/MultiPolygon 约束面；`mode=hard` 作为禁行格，`mode=soft` 按要素 `weight` 累加路线软代价。系统保存来源/类别和栅格命中信息，不推断数据完整性、保护距离或工程权重；点线要素须先按适用规则缓冲成面。
- 已补充台湾官方数据获取脚本：农业部自然保护区图层与环境部饮用水水源保护区 ZIP 可转换成带数据集编号、来源日期、许可证和 SHA-256 的 WGS84 GeoJSON；图层只以显式配置的软惩罚导出，不默认宣称为法定禁建区。20 米官方 DTM 资源和人口统计区边界/人口表的接入限制及后续工作记于 `公开数据与获取流程.md`。
- 海拔、地表坡度和地面高差硬阈值均需用户显式设置，默认关闭。旧台湾保护区缓存实际位于中国大陆，本次规划不使用该错误区域数据。

当前仓库中的模块化 CLI 已加入站点台账/任务读入、建筑代价和障碍、DEM 局部高差惩罚及纵断面输出，并由 `tests/test_station_planning.py` 覆盖。开发工作区另一个 `V5_final` 入口不在此仓库，本说明不将其状态视为已验证。当前仍缺少可核验站点、人口/住宅、官方保护区/生态红线、道路权属与交叉许可、塔位档距和导线净空数据，因此不能声称当前路线已满足完整工程约束。正式用例需要项目方先提供具来源记录的站点接入点和约束图层，再用勘察/设计结果校准权重和限制。

上述边界与官方标准的关注点一致：生态环境部 HJ 1113-2020 要求选线考虑环境敏感区、站端走廊及保护目标；HJ 24-2020 要求调查敏感目标的位置和建筑高度等信息。国家能源局的线路设计标准按电压等级分别适用，导线风偏等也需按档距、导线和杆塔参数计算。参考资料见 [HJ 1113-2020](https://www.mee.gov.cn/ywgz/fgbz/bz/bzwb/other/qt/202003/t20200305_767473.shtml)、[HJ 24-2020](https://www.mee.gov.cn/ywgz/fgbz/bz/bzwb/hxxhj/xgjcffbz/202012/W020201218709948943608.pdf)、[国家能源局标准名录](https://prpq.nea.gov.cn/uploads/file1/20240911/66e1071abaa30.pdf) 与[导线风偏答复](https://www.nea.gov.cn/2022-02/22/c_1310484332.htm)。

## 5. 运行方式

在软件目录运行。真实线仅用于规划结束后的评分：

```bash
python -m transmission_path_planner \
  --dem ./data/taiwan_dem_35m.tif \
  --real-cases-csv ../data/real_cases_tw/real_cases.csv \
  --out-dir ./results/unguided --no-ppp
```

不进行误差评估时，省略 `--real-cases-csv`、`--real-shp` 和 `--with-real`，程序仍会生成 A* 最终路线。旧版参考线引导参数已从当前 CLI 移除。

## 6. 本轮修改范围

- `transmission_path_planner/cli.py`：移除参考线引导、走廊惩罚、真实误差重试和误差选路；先按硬约束筛除不合格候选，优先选择可行 A*，仅在 A* 不可用时回退到首个可行 AI 候选。该规则不在 AI 候选间比较统一成本分数；真实线只在选路后读取作事后评估。
- `transmission_path_planner/io_export.py`：统一按 GeoJSON 规范输出经度、纬度顺序，修复最终路线坐标颠倒。
- `transmission_path_planner/config.py`：默认目录改为相对软件目录解析，优先查找随包 DEM，保留外部数据路径回退；当前 CLI 移除了无效且指向线路数据的 `--shp` 参数。
- `transmission_path_planner/osm.py`、`cli.py`：新增 `--osm-cache-dir`，接通工作区现有建筑/土地利用环境缓存；按要素包围盒预筛远离当前窗口的几何，避免对台湾全域多边形重复构造 Shapely 对象。
- `transmission_path_planner/methods.py`：A* 搜索状态改用栅格数组，TW173 全分辨率搜索从 146.8 秒降到 105.6 秒，结果和双向相似度指标保持一致。
- 本轮严格无线路先验复测：12 条线路使用 20 米来源 DEM、缓存建筑/土地利用与 A*，不启用 VIN/PPO/CostUNet，也不把线路网络、参考几何或走廊传入规划器。起终点作为规划任务输入，参考线只在选路后评分。双向 F1@100m 中位数 2.8%（范围 0.7%–10.3%），0/12 达到 95%；较差方向 P95 中位数 4.52 km。现有地形和不完整环境约束不能复原既有线路走向。完整口径、逐线指标和误差图见 `精度复测记录_20261022.md` 的“严格无线路先验规划复测”一节；DEM 来源及垂直基准仍有限制。
- `run_real_tw.bat`：仅运行算法规划和事后真实线路对照，不再传入引导参数。
- `transmission_path_planner/methods.py`、`smoothing.py`、`metrics.py`、`geometry.py`：修正 A* 启发式可采纳性、约束路径段验证及栅格像元坐标映射。旧版 `V5_final` 入口不在当前仓库，本次未核验其同步情况。
- `README.md`、站间设计说明及软著材料：说明线路网络和参考线不进入规划，更新缓存目录参数、登记源码稿与行数。
- `tests/test_cli_reference_independence.py`：验证误差变化不影响选路、CLI 不再暴露引导参数，并保留 A* 最优性、像元往返映射、硬约束平滑回退和 GeoJSON 坐标顺序检查。
- 旧版 `V5_final/simulation/server.py`、`web/app.js` 的独立原型曾记录未知格和对角角点约束修复；这些文件及 `test_server.py` 不在当前仓库，本次未复核。
- `transmission_path_planner/stations.py`、两套 CLI、`cost.py`、`osm.py`、`methods.py`、`metrics.py`：新增站间任务校验、建筑避让/建成区代价、地面高差惩罚和高程纵断面导出；配套空 CSV 模板和站间规划设计说明。
- `tests/test_station_planning.py`：覆盖站点任务、未知站点拒绝、建筑代价、高差约束和纵断面输出。
- `stations.py` 与当前模块化 CLI：增加站端实测地面高程、来源与垂直基准的读取和结果报告；缺测/来源缺失/基准不一致时不计算两端实测高差。
- `osm.py` 与当前模块化 CLI：增加带 `mode`、`source` 和软权重的 WGS84 GeoJSON 面约束；规划结果保存约束来源与覆盖栅格计数。
- 站间设计说明、README、软著说明材料及源程序稿：同步更新输入字段、GeoJSON 约束格式和登记源码分页统计。

本轮没有修改最初的 Word 计划书；上述对照说明可用于决定结题材料是否需要按实际完成内容修订。
