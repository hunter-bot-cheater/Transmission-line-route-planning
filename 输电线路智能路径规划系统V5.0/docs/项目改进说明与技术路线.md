# 项目改进说明与技术路线

本文根据《大创计划书_修改版.docx》梳理原计划与当前 V5.0 代码的差异，并记录本轮已落地的无引导改进。计划书是项目背景材料；本文不把尚未实现的计划内容描述为已完成成果。

## 1. 原计划与当前实现

计划书提出三阶段主线：先建立纯机器学习路径规划基线，再与 WOA/GWO/SSA、IPSO-SA 等方法比较，最后把学习算法与群体搜索融合，并接入“扫描—地图更新—路径优化”的动态流程。

当前 V5.0 登记范围主要解决山区输电线路静态选线，包含 26 维代价特征、VIN-Grad、PPO 和 A*，并附带 50/100 条线路的批量实验材料。核心包里尚未找到无人机覆盖扫描、观测后更新地图、动态重规划的可运行模块；计划书列出的 WOA/GWO/SSA 对照和在线融合也没有体现在这个 CLI 的主流程中。工作区另有 `V5_final/simulation/` 独立演示原型，覆盖合成地形生成、扫描揭示和已知区域 Dijkstra 重规划；它不读取真实 DEM 或无人机传感数据，不属于登记源代码范围，也没有接入 V5.0 CLI。应称作计划验证原型，不能写成真实地图上的在线系统。

## 2. 引导线痛点与本轮代码改动

以待规划线路的真实线作为“引导线”，会把测试答案提前交给规划器。原入口在检测到真实线时会自动增加走廊代价、给真实线附近解除硬约束，并用真实误差挑选 VIN/PPO 重试和最终路线；显式写 `--real-attract 0` 或 `--corridor-w 0` 也会被默认权重覆盖。没有真实线时，原流程又没有确定最终路线。

本轮已在 CLI 增加三种模式：

| 模式 | 规划时读取真实线 | 最终路线规则 | 适用情形 |
| --- | --- | --- | --- |
| `none`（默认） | 不读取真实线来构造代价、放宽硬约束、重试或选路 | 采用 A* 代价基线 | 无引导规划；若同时输入真实线，只在路径生成后计算指标 |
| `auto` | 有真实线时会引导 | 按参考误差选择 | 兼容旧实验；结果不作为无泄漏成绩 |
| `reference` | 明确使用真实线引导 | 按参考误差选择 | 研究“给定走廊后”的贴合能力 |

`--real-attract 0 --corridor-w 0` 现在可以显式关闭这两项引导。无引导模式按固定随机种子顺序生成 VIN/PPO 候选；只有路径无效时才重试，不以真实误差选择候选。最终路线用 A*，`selection_rule` 写入指标 JSON 与最终路线 GeoJSON。A* 启发式改用全图最小通行代价作为下界，平滑路线逐段检查硬约束；若捷径穿越禁行像元则回退到合法的原始路径。经纬度到栅格索引使用 Affine 逆变换并向下取整，确保格心坐标能映射回原像元。该模式保证推理时不读取目标线几何；若要宣称训练/测试完全无泄漏，还必须从训练数据和预训练权重中排除测试线路，并保存划分清单。

本轮还修正了 VIN 的值迭代目标：输入改为 A* 同源的像元代价和硬掩膜，8 邻域边按行列实际米距加权，屏蔽禁行邻格及对角切角，并统一目标状态值为零。VIN 仍是学习到的近似值场，未纳入 A* 使用的地面坡度边代价，所以继续将其作为候选方法而非最优性基线；新增障碍、各向异性步长和终点边界回归测试。

## 3. 当前证据能支持什么结论

随项目保存的无泄漏泛化报告记录：

- 50 条测试线：无泄漏候选池有 47/50 条包含满足报告阈值的路径；确定性自动选优约为 25/50。
- 扩展到 100 条后：候选池为 80/100，确定性长度规则选优为 42/100。

候选池达标是“至少有一个候选事后贴近真实线”的上限证据，不等于系统能在规划前自动识别该候选。自动选优明显较低，说明当前信息不足以可靠恢复工程师做出的结构性绕行决策。报告中的长度规则使用测试 CSV 的 `length_km` 作为已知线路长度先验；如果实际规划拿不到该字段，42/100 不能直接代表纯起终点场景。以上是历史报告里的结果，本轮未重跑实验；50 条与 100 条报告的分段误差阈值、候选集构成和选优规则有差异，引用时应逐项注明。还须核验 CostUNet 等模型权重的训练线路清单；仅在 CLI 运行时关闭引导，不能证明模型训练阶段没有见过测试线路。

## 4. 对引导线依赖的建议

真实线路的走向通常还受征地、既有通道、保护区、施工便道、塔位间距、跨越许可等未完整编码因素影响。仅凭起终点和 DEM/OSM，不能保证复原某一条已建线路。建议按以下顺序解决：

1. **把真值从规划接口移出。** 规划只输入起终点、DEM、合法禁建区、保护/避让规则及确实可获得的工程约束。真实线只在独立评估步骤加载。
2. **将隐性“引导线”换成可审计约束。** 需要工程人员给方向信息时，输入宽走廊面、必经点、禁入面或塔位范围，并在结果中记录其来源和权重。不要把测试线路的精确坐标伪装成普通先验。
3. **用留线/留区验证既有网络先验。** `corridor.py` 已有精确匹配留一排除工具，可用于排除同一目标线；正式泛化评估还应按线路族、相邻走廊或地理区域分组，避免重复/近邻线路落入训练集和测试集两侧。
4. **把输出定位为候选方案集。** 用多组可解释的代价权重和转向惩罚生成互相有差异的候选，再按硬约束、建设代价、绕行率、跨越风险、曲率和塔位可行性排序，提供工程师复核。当前 50/100 条实验支持候选池比单条自动选路更稳，但 CLI 的多参数候选池尚未集成到生产入口。
5. **把现有动态扫描原型逐步接入真实数据。** 当前 `V5_final/simulation/` 已覆盖合成地图、扫描覆盖度、观测掩码和周期性 Dijkstra 重规划；下一步要接入真实 DEM/传感器增量，记录每轮代价图变化，并在相同预算下比较固定 A*、重规划 A*、PPO 与融合策略。训练/测试按地图或区域隔离，并报告多随机种子的均值和波动，才能验证动态融合增益。

### 4.1 将规划对象改为站点间线路任务

用户提出的站点问题成立。工程任务连接的是已确定的变电站或线路接入点；只给任意两个经纬度无法表达线路归属、电压等级和站端进出线位置。此前 `real_cases.csv` 的端点来自评估线路几何首末点，现有工作区也没有经过核验的变电站台账，不能把这些测试点冒充站点。新的 `stations.csv` 与 `route_tasks.csv` 负责把站点身份、接入坐标和待规划任务绑定起来。站点选址仍与固定站点间的走廊规划分开处理。

站点间高差、沿线地形、居民建成区以及禁入区域确实会影响候选路线。当前实现对可用数据采取分层处理：

- 搜索将站端接入点映射到其所在 DEM 像元；输出路线首尾恢复用户提供的精确坐标，并记录到像元中心的距离。若接入点所在像元是 DEM 空值、已映射建筑或启用的禁区，规划报错，不静默移动到最近可通行像元。
- DEM 表面坡度、粗糙度和相邻像元高差参与路线代价；显式配置地面高差上限时，会在平滑、端点恢复之后再次检查所有候选路线。输出端点 DEM 高程差、累计升降、最大采样地面坡度和 `elevation_profile.csv`。这些是地形筛查指标，不是导线弧垂/净空或塔位可行性计算。
- 站点台账可选提供测量地面高程、来源和垂直基准。仅当两端测量与来源齐全、基准一致时才单独报告实测高差；它不会覆盖 DEM 值或自动成为路线阈值。
- OSM 建筑轮廓作为当前可用的硬障碍；平滑建筑密度与住宅用地标记合成建成区代理软代价。其他 OSM 图层只作为特征/可选模型输入，不构成默认硬避让；结果记录图层缓存和观测范围状态。OSM 覆盖不完整，也无法区分完整住宅、人口和敏感目标；默认避让只覆盖数据中映射的建筑足迹。
- 可通过 `--constraint-geojson` 加载带来源记录的 WGS84 Polygon/MultiPolygon 约束面；`mode=hard` 作为禁行格，`mode=soft` 按要素 `weight` 累加路线软代价。系统保存来源/类别和栅格命中信息，不推断数据完整性、保护距离或工程权重；点线要素须先按适用规则缓冲成面。
- 已补充台湾官方数据获取脚本：农业部自然保护区图层与环境部饮用水水源保护区 ZIP 可转换成带数据集编号、来源日期、许可证和 SHA-256 的 WGS84 GeoJSON；图层只以显式配置的软惩罚导出，不默认宣称为法定禁建区。20 米官方 DTM 资源和人口统计区边界/人口表的接入限制及后续工作记于 `公开数据与获取流程.md`。
- 海拔、地表坡度和地面高差硬阈值均需用户显式设置，默认关闭。旧台湾保护区缓存实际位于中国大陆，本次规划不使用该错误区域数据。

已在模块化 CLI 和 `V5_final/scripts/ai_path_planning_v5.py` 中加入站点台账/任务读入、建筑代价和障碍、DEM 局部高差惩罚及纵断面输出，并补充了 `tests/test_station_planning.py`。目前缺少可核验站点、人口/住宅、官方保护区/生态红线、道路权属与交叉许可、塔位档距和导线净空数据，因此不能声称当前路线已满足完整工程约束。正式用例需要项目方先提供具来源记录的站点接入点和约束图层，再用勘察/设计结果校准权重和限制。

上述边界与官方标准的关注点一致：生态环境部 HJ 1113-2020 要求选线考虑环境敏感区、站端走廊及保护目标；HJ 24-2020 要求调查敏感目标的位置和建筑高度等信息。国家能源局的线路设计标准按电压等级分别适用，导线风偏等也需按档距、导线和杆塔参数计算。参考资料见 [HJ 1113-2020](https://www.mee.gov.cn/ywgz/fgbz/bz/bzwb/other/qt/202003/t20200305_767473.shtml)、[HJ 24-2020](https://www.mee.gov.cn/ywgz/fgbz/bz/bzwb/hxxhj/xgjcffbz/202012/W020201218709948943608.pdf)、[国家能源局标准名录](https://prpq.nea.gov.cn/uploads/file1/20240911/66e1071abaa30.pdf) 与[导线风偏答复](https://www.nea.gov.cn/2022-02/22/c_1310484332.htm)。

## 5. 运行方式

在软件目录运行。给真实线评分但不让它引导规划：

```bash
python -m transmission_path_planner \
  --dem ./data/taiwan_dem_35m.tif \
  --real-cases-csv ../data/real_cases_tw/real_cases.csv \
  --out-dir ./results/unguided \
  --guide-mode none --no-ppp
```

完全没有参考线时，省略 `--real-cases-csv`，仍会生成 A* 最终路线，但无法计算与真实线路的误差。若需要展示“给定参考线后”的表现，显式使用 `--guide-mode reference`，并将其报告标注为参考线引导结果。

## 6. 本轮修改范围

- `transmission_path_planner/cli.py`：区分规划引导与事后评估；无引导时不按验收线挑选重试或最终路线；补齐无参考线路时的 A* 最终输出；允许权重设为 0。
- `transmission_path_planner/io_export.py`：统一按 GeoJSON 规范输出经度、纬度顺序，修复最终路线坐标颠倒。
- `transmission_path_planner/config.py`：默认目录改为相对软件目录解析，优先查找随包 DEM，保留外部数据路径回退。
- `run_real_tw.bat`：改为当前 CLI 支持的参数，并显式传入随软件包提供的 DEM。
- `V5_final/scripts/ai_path_planning_v5.py`、`V5_final/run_real_tw.bat`：为原始实际入口加入同一套 `--guide-mode`，台湾留出线路批处理默认改为无引导评估。
- `transmission_path_planner/methods.py`、`smoothing.py`、`metrics.py`、`geometry.py`：修正 A* 启发式可采纳性、约束路径段验证及栅格像元坐标映射；根目录 V5 入口同步了相同修复。
- `README.md`、`软著材料/软件说明书.md`：更新引导模式、运行命令和无引导结果解释。
- `tests/test_cli_guidance.py`：覆盖默认无引导、旧模式兼容、选路规则、A* 最优性、像元往返映射、硬约束平滑回退和 GeoJSON 坐标顺序。
- `V5_final/tests/test_route_guidance.py`：覆盖默认无引导、显式零权重、A* 最优性、像元往返映射和硬约束平滑回退。
- `V5_final/simulation/server.py`、`web/app.js`：阻止对角路线穿越未观测区或硬障碍角点，并屏蔽发送给规划器的未知格代价；`test_server.py` 覆盖该边界。
- `transmission_path_planner/stations.py`、两套 CLI、`cost.py`、`osm.py`、`methods.py`、`metrics.py`：新增站间任务校验、建筑避让/建成区代价、地面高差惩罚和高程纵断面导出；配套空 CSV 模板和站间规划设计说明。
- `tests/test_station_planning.py`：覆盖站点任务、未知站点拒绝、建筑代价、高差约束和纵断面输出。
- `stations.py` 与两套规划入口：增加站端实测地面高程、来源与垂直基准的读取和结果报告；缺测/来源缺失/基准不一致时不计算两端实测高差。
- `osm.py` 与两套规划入口：增加带 `mode`、`source` 和软权重的 WGS84 GeoJSON 面约束；规划结果保存约束来源与覆盖栅格计数。
- 站间设计说明、README、软著说明材料及源程序稿：同步更新输入字段、GeoJSON 约束格式和登记源码分页统计。

本轮没有修改最初的 Word 计划书；上述对照说明可用于决定结题材料是否需要按实际完成内容修订。
