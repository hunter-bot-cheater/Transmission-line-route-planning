# 输电线路规划开源方案与问题建模

调研日期：2026-10-24
建模边界：规划阶段不读取既有线路内部几何、塔位或由它们生成的走廊作为寻路先验；站点端点是规划任务必需输入，应来自独立核验的站点数据。当前 12 线基准 CSV 端点与配对参考 SHP 首尾点几乎重合，而 CSV 来源尚无可追溯元数据，因此它只支持“固定端点条件下”的后验比较，不能作为“输入也完全独立于历史线”的严格盲测。

## 结论

普通栅格 A* 可以回答“在给定阻力面上，哪条像元路径的累计成本最低”，但架空输电线路还要回答“杆塔落在哪里、相邻塔能否形成可行档距、转角是否可接受、导线跨越地形和障碍是否可行”。因此，适合本项目长期目标的核心模型应是**塔位候选点图 + 可行跨距边 + 工程约束下的最短路/多目标路径**。栅格成本面仍可用于计算塔位成本和跨越成本，A* 保留为无塔位约束的基线。

这也划清了误差验收边界：只给地形和公开约束，不能唯一推断某条既有线路的历史走廊。征地、地权、审批、塔型、运维、未公开地质资料和历史决策都可能改变实际线位。不能把“新线规划可行”与“历史线路 100 米内复刻”当成同一指标。

### 开源代码复核后的实现判断

- PowerPlanner 的 README 明确采用“候选塔位作图节点、允许的最小/最大塔间距作边”，并把塔位成本、导线经过成本和相邻边角度成本分开；角度惩罚不能只靠普通的单一像元 A* 状态表示。它是本项目转向塔位图的最直接算法参照，但仓库自述为硕士论文代码，README 指向较少依赖的 LION 包。论文提出最小角度 Bellman-Ford、低内存迭代方法和 k 条多样路线；这些是算法参照，不替代本项目缺少的塔型、导线、净空与许可输入。
- PYORPS 的核心 README 仍定位于地下电缆最小成本选线；新版列出了多指标成本面、cost-field 复用和 overhead tower fields，但作者同时将 siting/collector/costmodel/certify 标为 research code、非稳定 API。适合借鉴数据管线和栅格实验，不宜直接将其塔位子包视为已验证的架空工程引擎。
- ATLDP README 的当前状态比路线搜索工具更偏后段工程设计：已经有路线/POI和手动塔位、塔型/跨距与弧垂张力设计步骤，但自动塔位优化仍列为后续，且项目明确要求不要用于生产线路设计。它值得用于梳理“路线候选最终要交给什么工程校核”，不构成当前规划器的自动路线算法替代品。
- ETH Zurich 3D DSS 强调 Pareto 路线备选和利益相关者多目标，而不是用一个未经讨论的加权和伪装成唯一最优路线；还将山谷、居民影响、景观可视性和既有设施共廊列为模型因素。对本项目可借鉴方案输出与解释方式，但这些目标需要当地数据和利益相关者决策，不能凭公开 DEM 自动推断。
- PowerLine-GIS 的仓库已归档，研究流程包含多权重组合路径和与既有路径重叠的后验评价。它可帮助核对多因素 GIS 工作流，但其中的历史线路重叠评价不能变成本项目寻路输入，否则会违反本项目“不使用历史路线先验”的验证边界。
- 上述论文和仓库验证的是特定输入成本下的优化、可行性或方案比较，没有证明仅依赖 DEM/公开约束就能把新规划线压到既有线 100 米内。线路偏离既有线的公里级量级，不能靠换一个图搜索器自动消失；必须先补上能够解释真实走廊选择的独立工程/权属/许可数据，并同时保持参考线路只用于最终盲评。
- 本项目最近 12 线基准使用 `real_cases.csv` 提供站间端点；已核对 CSV 与配对 SHP 的端点相距约 0.05–0.06 m，但 CSV 缺来源、版本与处理记录。CLI 在这些端点上规划、再于选路后读取参考 SHP 评分，所以内部线路形状没有进入寻路；端点是否由参考线派生仍无法排除。下一次严格盲测必须改用可追溯的独立站点/接入点坐标，并重新跑完整批次，不能仅沿用这批结果宣称“完全不含历史信息”。

## 建议的算法分层

1. **固定站点与数据基准。** 站点坐标作为线路端点；所有输入层统一到米制投影、垂直基准和明确分辨率。每层记录来源、时间、覆盖率、NoData 和精度。
2. **拆分硬约束与软成本。** 法定禁入区、不可跨越水域、DEM 无效区、线路工程限制作为硬约束；建设成本、地形难度、人口暴露和环境影响作为可解释的分项成本。不能把缺数据默认为低成本。
3. **建立塔位候选图。** 在可建区域生成候选塔位节点，并为节点计算地基/坡度/土地成本。只在最大/最小档距、转角和可达性满足要求时连接两个塔位；对每条候选跨距沿导线走廊采样 DEM、障碍物和成本层。
4. **求解有工程语义的路径。** 用最短路或动态规划联合优化节点与跨距；把转角代价放入状态/边转移，而不是先得到像元路线后再随意折线化。返回多条近优且空间上不同的候选，让代价分项和可行性可解释。
5. **完整复核和稳定性检查。** 对最终真实坐标折线重新检查建筑、禁区、坡度、档距、塔位角度和数据覆盖；对栅格原点、分辨率和合理成本扰动重复规划，报告路线走廊变化，而不是只报告一次 A* 的长度。

### 最小候选塔位图的数据结构

- **节点**表示固定站端或候选塔位，包含坐标、地面高程及基准、塔型可用性、塔基可行状态、禁建原因和输入数据覆盖状态。站端接入点固定，不自动平移。
- **有向边**表示相邻杆塔间的候选跨距，包含水平距离、方向/转角、沿线地表剖面、跨越物类别、线性成本与校核状态。只有跨度、塔型/转角、许可和导线净空均满足输入的工程规则时，边才能进入可行图。
- 求解状态应在需要转角代价时记录上一跨方向。塔位成本按节点计一次，跨距施工/导线/跨越成本按边计，避免重复计费。缺少可信货币成本和优先级时输出非支配方案集，不虚构权重选出唯一“最优”。
- 为控制规模，先以地表成本和约束形成筛查走廊，再在走廊内布置候选塔位；只检查最大允许档距范围内邻点。走廊宽度、候选间距和工程参数都需要项目数据或收敛实验确定，不设臆造的生产默认值。

塔位方案需要额外输出 `tower_schedule.csv`、`span_schedule.csv` 和逐项校核报告。当前项目缺少经确认的导线/地线型号、塔型、允许档距/转角、弧垂张力参数、风冰工况、DSM/LiDAR 地物高度、基础地质和许可数据；在这些信息补齐前，塔位图只能作为可行性原型，不能声称完成架空线工程校核。

建议的合成验收先用小图穷举验证 Dijkstra 最短路，再人为设置超跨度、转角不允许、塔基禁入但导线允许跨越、建筑净空不足和 DEM/DSM 缺测等场景。每种失败都应给出边被拒原因；未知覆盖必须是“未评估”，不能当成可行。全部夹具数值只用于测试，不能成为生产默认值。

## 当前迭代的落点

- 本轮保留现有 A* 搜索作为基线，增加“整段直连仅在硬约束、地面坡度限制和连续代价均通过时才替换”的局部去锯齿步骤。该步骤改善的是栅格方向偏差，不会自动解决塔位布置或真实线路重建。
- 合成稳定性实验表明，软成本接近时，分辨率或居民/风险权重的 10% 改变都可能切换竞争走廊。因此，不应仅凭单一加权和输出一个看似确定的方案；需要保留多个近优选项并公开各项代价与稳定性。
- 规划算法不得使用历史线路来调权、设搜索走廊或挑候选。真实线路指标只在模型冻结后用于独立盲测；不达标应记录为模型与信息边界，不得反过来泄漏进参数。
