# 实验塔位图内存优化（2026-10-25）

## 改动

`tower_graph_route` 原先为所有候选点创建 Python 坐标元组、去重集合、节点字典、逐行元组列表、全节点空邻接表、全节点就绪标记和全局已检查边集合。现在通过 NumPy 生成按行优先排序的候选坐标，二分插入最多两个端点；按行偏移查询跨度范围；只缓存搜索展开节点的邻接表，并移除全局边/方向代价字典。边代价统一按节点 ID 小到大计算，避免反向重复计算产生浮点末位差异；转弯模式通过有序邻接表二分查找上一跨代价。

候选塔位、跨度条件、穿越栅格、DEM 净空屏查和目标函数均未改变。等代价多条路线的内部邻居顺序可能变化；因此逐点路线回归与目标值/可行性回归都保留检查。

## 合成开图对照

相同环境：Windows 11、Python 3.13.6、NumPy 2.3.4、Intel x64、35 米方形像元、`candidate_stride=2`、跨度 175–350 米、单位通行代价、全通行栅格。RSS 通过 `psutil` 每 2 ms 采样。旧版源码取 Git 提交 `c35db305fdbd4a5e072ba0fbc032155cfcdc1323`；新旧两组端点、栅格、参数一致。

| 网格 | 旧版中位耗时 | 新版中位耗时 | 旧版峰值 RSS 增量 | 新版峰值 RSS 增量 | 新版提速 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 128² | 0.039 s | 0.042 s | 未采集 | 1.51 MB | 0.92× |
| 256² | 0.076 s | 0.078 s | 未采集 | 3.94 MB | 0.97× |
| 512² | 0.226 s | 0.152 s | 未采集 | 7.32 MB | 1.48× |
| 1024² | 0.853 s | 0.363 s | 125.83 MB | 30.88 MB | 2.35× |
| 2048² | 4.145 s | 0.724 s | 455.02 MB | 125.16 MB | 5.72× |
| 4096² | 未测旧版 | 3.251 s | 未测旧版 | 493.27 MB | 未比较 |

在这组均匀开图中，新实现 1024² 与 2048² 的峰值 RSS 增量分别下降约 75% 和 73%。旧版 1024²/2048² RSS 是隔离执行旧提交时采得的单次峰值；新版峰值包含预热和三次复跑。新版 4096² 峰值 RSS 约 1.08 GB（从进程基线增加约 493 MB），中位耗时 3.251 秒；旧版没有在 4096² 上运行，因此不作速度/内存对比。小图的节点构建固定开销接近旧版；512²及以上显著降低耗时，大网格同时减少了大量峰值内存。

新旧输出对照中，128²、256²、512²、1024²、2048² 五种开图的路线坐标逐点相同；跨墙图在转弯权重 0 与 0.5 下也逐点相同。分数端点、硬墙、对角阻挡、候选步长、站点代价和 DEM 净空等回归由现有测试覆盖。

## 重现

当前实现的原始计时、峰值 RSS 样本与运行环境写入被 Git 忽略的 `outputs/tower_graph_final_lazy_memory_20261025.json`。命令：

```powershell
D:\python\python.exe tools\benchmark_tower_graph.py `
  --sizes 1024 2048 4096 `
  --repeats 3 `
  --output outputs\tower_graph_final_lazy_memory_20261025.json
```

在同一 4096² 合成输入上另行交替比较 `np.unique(nodes[:, 0], return_index=True)` 和相邻行变化扫描，旧方案/线性方案的耗时中位数分别为 3.272/3.293 秒，路线完全相同。线性方案没有显示显著耗时收益；保留它是为了避免对已排序的数百万行标签重复排序，并降低行索引构造的临时内存。

要复跑旧版峰值对照，在独立 checkout `c35db305fdbd4a5e072ba0fbc032155cfcdc1323` 上用相同网格和参数调用 `tower_graph_route`，以当前基准工具的 2 ms RSS 采样方式记录进程 RSS。旧版工具没有峰值 RSS 字段；报告中旧版峰值数据来自本次旧提交隔离执行，不应与其他机器上的工作集预测混为一谈。

## 限制与后续

- 所有计时和 RSS 数字来自全通行、单位代价的合成图，不代表含复杂硬障碍、DEM 净空剖面或塔位限制的实际案例。
- 4096² 新版峰值 RSS 仍约 1.08 GB（含 Python、输入栅格和依赖基线），且节点坐标数组仍随候选点数线性增长；该数据只是全开合成图，不足以宣称 4096² 实际约束图层任务适合服务器运行。
- 默认规划仍使用普通栅格 A*；塔位图是显式实验筛查模式，不能替代经核验的站端、杆塔、档距、弧垂和净空设计资料。
