### 成本层边界与验证

目前规则代价由地形坡度/粗糙度和建成区软代理构成，建筑足迹及用户明确提供的约束另作硬掩膜。本轮代码把 OSM 土地利用编码 4（住宅、零售、商业、城市）补入已有建成区代理，与建筑密度及住宅面取最大值，复用现有 settlement 权重，不再叠加重复罚分。缓存审计发现实际 OSM 文件把标签保存为 `{"tags": "{'landuse': 'commercial', ...}"}`，加载器此前没有解包；同时土地利用编码函数也曾未导入。因此旧缓存中的土地利用分类和住宅掩膜均未生效。现已用 `ast.literal_eval` 安全解析旧格式，记录包装标签数与解析失败数，并以真实包装结构覆盖商业编码、住宅掩膜及异常计数的回归测试。此修复恢复的是已有 OSM 土地利用数据，不代表接入了新的官方数据源。12 条线路的完整配对 A/B 已完成，结果见下节。

### 12 条线路配对复测

在同一 20 米来源 DEM、相同端点和 A* 设置下，对比旧基线与标签解析修复及建成区软代价。规划结束后才读取参考线路用于评分；未把参考线几何输入选线过程。结果文件和图保存在 `D:\大创\results\cost_layer_builtup_legacy_tags_fixed_12_20261022_v3\`。

| 指标 | 旧基线 | 本轮 | 配对结果 |
| --- | ---: | ---: | --- |
| F1@100m 中位数 / 均值 | 2.83% / 3.37% | 2.52% / 3.12% | 改善 2 条、持平 2 条、变差 8 条；中位变化 -0.024 个百分点 |
| 两方向 P95 较大值的中位数 | 4.520 km | 4.508 km | 改善 5 条、持平 5 条、变差 2 条（两方向 P95 差值绝对值 ≤1 米记持平） |
| F1@100m 达到 95% 的线路 | 0/12 | 0/12 | 本轮未达到目标 |
| 路径完全相同 / 发生变化 | — | — | 2 条相同、10 条变化 |

12 条都完成规划；在本批次已启用的硬掩膜下，最终路线复核均无硬约束栅格违规。但本次没有配置地面坡度阈值，也没有塔位、档距、导线净空、交叉许可和现场地质等工程数据，所以“无已配置栅格违规”不代表工程可行。F1@100m 是两个方向长度覆盖率的调和平均，应同时查看方向值；距离采样间隔约 20 米，报告的 P95 定义为两个方向分别计算后取较大值（较差方向 P95），不是合并样点后的 P95。配对比较中，两方向 P95 差值绝对值不超过 1 米记为持平；均值和中位数对 12 条线路等权，不按线路长度加权。12 条样例端点来自参考线路 CSV，且已多轮用于开发诊断，不是独立泛化测试。此次新增建成区代价没有带来有意义的贴线改善，不能据此继续调权重追逐参考线；下一步应优先取得可核验的官方用地/建筑、人口暴露与地质灾害数据，并按单层 A/B 评估其覆盖、工程含义和路线变化。

逐线指标见 `paired_ab_summary.csv`，汇总报告见 `paired_ab_report.md`，配对图见 `paired_ab_comparison.png`（均位于上述结果目录）。

纯 A* 且未启用 VIN/CostUNet 时，执行路径只加载建筑、土地利用代价/硬掩膜所需波段；道路、水系、铁路等模型/诊断波段在输出元数据中标记为 `not_loaded`，不能把它解释为“已检查且无要素”。建筑净距只在显式设置正的 `--building-clearance-m` 时计算。启用 VIN/CostUNet 时仍计算完整特征波段。该按需计算不改变 A* 使用的代价栅格或建筑硬掩膜。

道路、铁路、水域、植被虽已有 OSM 特征波段，但这些缓存只说明观测到要素，不代表完整覆盖；输电线跨越水域/铁路可以通过设计解决，因此不能简单按距线远近一律避让。另经缓存标签审计，`taiwan_faults.pkl` 的 699 条要素实际是 545 条悬崖和 154 条山脊，没有 `geological=fault`，故不能作为断层风险层使用；现有 `dist_fault` 模型特征名称与内容不符，纳入模型前还需核对训练数据和权重兼容性。缺少覆盖评估和工程代价依据前，不把这些图层任意加到默认 A* 权重。后续接入每层时，应保留独立栅格、数据来源/日期/CRS/覆盖状态，先单层 A/B，再做组合；所有风险潜势默认作为可解释的软筛选因素，法定禁区才作为硬约束。

## 高精度图层优先级

1. **地形**：先获取官方 2025/2026 版 20 米 DTM 中覆盖样例线路的原始图幅，优先使用较新且元数据完整的版本，再与未知来源的本地 35 米 DEM 对齐、核对 DTM/DSM 类型、坐标系、高程基准、测制年份及 NoData。20 米网格更细，但官方定位是概略分析；没有独立控制点验证前，不报告绝对高程精度。官方 5 米及更细数据受限，不能从 6 米渲染图砖或 1 米受限服务推导数值地形。
2. **建筑和用地**：优先取得有授权的 NLSC BUILD 建物轮廓与 1/5,000 国土利用现况矢量；OSM 继续仅作缺漏补充。建筑本体可作障碍，用地和住宅分类作为软代价，并把法定退缩、安全净距另行参数化。
3. **居民暴露**：把同年度统计区人口与最小统计区边界相连，作为居住区以外的补充软代价。它无法替代逐栋住户、学校/医院等敏感点或现场踏勘。
4. **线路工程约束**：找到台电公开电杆点位，但没有找到可公开下载、可核验精度的全台输电线实测走廊/逐档输电铁塔数据。若要让规划接近实际线路，关键输入是线路权属单位授权的站点坐标、输电塔位、档距/净空、既有通道、交叉跨越和许可边界；缺少这些数据时，只能做走廊筛查，不能把参考 SHP 偏差称为工程定位误差。

## 下载保护区筛查图层

在 `输电线路智能路径规划系统V5.0` 目录执行：

```powershell
python scripts/fetch_taiwan_constraints.py --soft-weight 1.0
```

脚本从农业部清单中挑选最近的 SHP 版自然保护区数据，下载环境部当前公开的 ZIP，并将两组面数据转为 WGS84 GeoJSON，输出至 `data/official_constraints.geojson`。原始 ZIP 缓存在 `data/official_constraints_cache/`；两个目录均属于外部数据，不随 Git 仓库提交。

需要自动追踪环境部最新文件时，先到环境部平台注册取得 API Key，再运行：

```powershell
$env:MOENV_API_KEY = "你的环境部 API Key"
python scripts/fetch_taiwan_constraints.py --soft-weight 1.0
```

也可用 `--moenv-file-url` 手动指定环境部 ZIP 下载地址。脚本会检查 ZIP 路径，转换图层前拒绝缺失 CRS 的输入，并将几何重投影到 WGS84；输出记录下载链接、数据集编号、源日期、来源图层、许可和 ZIP 的 SHA-256。

规划时显式加载生成的图层：

```powershell
python -m transmission_path_planner `
  --dem ./data/taiwan_dem_35m.tif `
  --stations-csv ./examples/stations.csv `
  --route-tasks-csv ./examples/route_tasks.csv `
  --constraint-geojson ./data/official_constraints.geojson `
  --out-dir ./results/station_routes --no-ppp
```

脚本仅生成 `mode=soft` 的图层，`--soft-weight` 必须由项目人员显式填写。权重是路线筛查偏好，不是法定避让距离或工程标准。只有在核对公告、边界、适用法规及审批结论后，项目人员才可把确定禁止的具体要素另行设置成硬约束。没有命中要素不能解释为没有敏感区；应检查源数据日期、覆盖区域、坐标系和规划输出中的 `constraint_layer_metadata`。

## 高分辨率数据接入与当前瓶颈

- 规划器原先默认将走廊最长边压到 480 像元。现有 12 个台湾样例窗口原始最长边约 1,121–2,972 像元，旧默认会把约 35 米输入网格降到约 120–220 米工作像元；这比更换成 20 米 DTM 前就先损失了地形细节。当前默认最长边已提高到 4,096，覆盖这些样例的原始窗口，不再因该参数降采样；日志会同时报告输入/工作网格、原始/实际像元和降采样倍率。若内存不足可显式调低 `--max-side`，规划输出会记录实际网格尺度。
- 现有本地 35 米 DEM 没有可验证的数据集来源、版本或垂直基准，因此提高工作网格只能保留该文件的原始细节，不能证明它本身比 35 米更准确。下一步应获取公开 20 米 DTM 原始图幅，逐幅校验 CRS、垂直基准、测制年份与 NoData 覆盖后再生成 GeoTIFF；未完成这些检查前，不把未知来源文件替换成“官方高精度 DEM”。
- 官方 BUILD 建物面通过本地输入准备，不会由脚本自动抓取受申请限制的 WFS：

```powershell
python scripts/prepare_official_buildings.py `
  --input .\data\authorized\BUILD.shp `
  --output .\data\official_buildings.geojson `
  --source-date 2026-08 `
  --license-note "按核准之学术研究用途使用"
```

随后通过 `--constraint-geojson .\data\official_buildings.geojson` 加载。建筑面按硬障碍栅格化，但这只屏蔽建筑本体覆盖像元，不自动添加法定安全距离、导线净空或塔位限制。

## 尚未自动化的数据与工程校核

- 官方 2025/2026 DTM 页面和 20 米开放服务已核实；官方图幅索引在当前环境无法稳定取得，TGOS 原始 ZIP 请求返回 HTTP 403，因此尚未获得可核验来源的官方原始栅格。另有一份第三方镜像 TIFF 用于路线对照：其字节 SHA-256 与镜像项目公布值一致，但这不是官方签名或官方校验和；读取文件自带 CRS（未覆盖源 CRS），以双线性方式重投影到 EPSG:4326，输出尺寸 10172×18872。源文件未标明并验证垂直基准，不能把这次对照当作工程高程精度证据。该次统计采用旧版 v1 组合误差和内部 8% 阈值，现已归档为历史口径，不代表当前程序的视觉相似度评分；当前 v2 双向空间指标及逐线复算见 `路线视觉相似度复测记录_20261022.md`。两者不是严格分辨率对照：10 条 20 米来源线路的实际工作像元约 23.1–33.6 米，TW173 的精确网格日志缺失；按旧版 v1 误差统计有 6 例降低、6 例升高，不能据此宣称精度普遍提升。逐线指标、运行状态和数据限制见 `精度复测记录_20261022.md`。公开的 2026 quantized-mesh 地形副本最高级别样例瓦片仅含 557 个高程顶点，属于简化三角网，不能据此还原可信的 20 米规则栅格；官方原件仍需核验 CRS、垂直基准、年份、NoData 覆盖后再考虑替换。
- 台湾统计区人口数据可与最小统计区边界联结，下一步可生成按人口加权的软避让面。边界和人口表需采用同一年度、同一统计区代码；小统计区或抑制值应按发布说明处理。
- 公开数据未覆盖征地、既有通道许可、交叉跨越审批、逐档塔位、导线弧垂/净空和全部敏感目标。本软件仍定位于前期走廊筛查，不输出可建设性结论。
