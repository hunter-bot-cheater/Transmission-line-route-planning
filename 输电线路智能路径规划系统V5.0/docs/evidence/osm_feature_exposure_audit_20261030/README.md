# OSM 道路、水系与铁路暴露审计（2026-10-30）

## 结论

本报告对已冻结的 18 条候选线路做事后空间暴露检查，用于判断现有 OSM 道路、水系、铁路缓存是否足以支持把这些图层加入规划代价。结果显示不同案例和图层的关系不一致；缓存快照日期未知，覆盖不完整。因此本轮没有把这些图层加入路线规划的硬约束或代价，也没有重跑规划器。

路线候选、缓存读取、指标计算和制图均在用户指定服务器 `/data1/B24041626/pp` 完成。本目录是服务器产物的只读副本。脚本是事后评估程序，不读取线路先验来生成路线，也不修改服务器已有数据。

## 候选隔离与验证

输入候选来自服务器 `dtm_2026_native_20m_3case_6400_20261028/results`。评估程序在读取任何真实线路几何前先验证：源运行状态为 `complete`；运行摘要和冻结文件均声明规划阶段未读取真实线路；冻结文件哈希与运行摘要一致；计划哈希一致；18 个候选文件全部存在且 SHA-256 一致；所有规划子进程成功，规划命令没有 `--real*` 或 `--reference*` 参数。

验证结果：18 个候选、0 个哈希失败。冻结清单 SHA-256：`e26c84b831f389339c4b214703a357b4d59d1032e1ec1e9747c7c030aa623b89`。源运行摘要 SHA-256：`0fe7c06159057edf78a76078642438aa0b534c10f4e2c35a463d56eacd84da22`。之后才读取 `TW59`、`TW345`、`TW102` 的真实线路 shapefile，并核对其投影长度与既有事后评分表差异小于 20 米。

每个案例包含 6 条规划候选（3 种搜索方法 × 2 种 WorldPop NoData 处理策略）和 1 条真实线路参照。真实线路只用于本次事后比较。

## 指标方法

- 真实线路和候选线统一投影至 EPSG:3826。
- 沿线路以 50 米间距采样，计算到缓存中最近道路、水系、铁路几何的距离，并汇总 P50、P90、P95 及 25、50、100、250、500、1000 米阈值内线路比例。
- 统计与缓存线状要素的几何相交；沿线 15 米内的重复相交按同一处去重，并记录线状重叠长度。
- `route_exposure.csv` 的距离和交叉数描述的是“与现有缓存里可观察要素的空间关系”，不是路线相似度、施工可行性或法律许可结论。缓存里没有要素也不能证明地面上没有该要素。

这批归一化缓存没有保存 Overpass 的 `timestamp_osm_base`；文件修改时间为 Unix epoch，不能用于推断数据快照日期。缓存构建器还会剥离源 Overpass 时间戳。道路请求只纳入 motorway、trunk、primary、secondary、tertiary 等类别，并不覆盖所有道路等级。各类 OSM 要素的完整性都未知；审计范围内的要素计数不构成全台覆盖证明。

## 代码与服务器验证

`audit_osm_feature_exposure.py` 只在服务器执行，生成此目录中的 CSV、JSON 和三张案例图。该程序会拒绝覆盖已存在的输出目录，并在读取真实线路前完成候选冻结和文件哈希验证。

`transmission_path_planner/osm.py` 的定向改动让加载器在可用时保留缓存生成器和源快照时间；若缓存没有记录时间，则明确返回 `source_snapshot_status=unknown_not_recorded`。服务器实际缓存验证返回生成器 `rebuild_osm_cache (shared)`、时间 `None`、状态 `unknown_not_recorded`。

服务器虚拟环境运行 `test_osm_settlement_metadata`：25 项测试通过。测试覆盖已记录的 Overpass 时间戳能被保留，以及重建缓存缺少时间时明确标记未知。
