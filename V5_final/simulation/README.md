# V5 无人机地形扫描与动态路径规划

## 实现路线

1. 按请求种子生成包含 33 个合成图层的地形，水域沿合成谷地分布并包含内陆硬约束河段；在线服务用每进程随机盐派生实际地形种子，同一进程内相同参数可复现，服务重启后不保证相同。完整真值仅保存在服务端会话中；默认起终点会吸附到最近可通行格。离线基准使用独立固定盐，以便跨进程复测。
2. 默认地图覆盖约 7.2 × 5.4 公里，分辨率为 50 米/格（144 × 108）；地形尺度按实际米数生成，网格加密不会缩小地图范围。无人机每个航段按不超过 1.5 格（75 米）的间距读取半径 4 格（200 米）的圆形足迹；重复覆盖通过在线均值融合，并返回样本数与 `n/(n+2)` 置信度。连续值图层叠加可重复的高斯测量噪声；道路、土地利用、保护区、铁路、断裂带、既有线路和硬约束图层按精确分类观测处理。
3. 服务端从已融合图层更新多因子代价场，未观测格保持空值。规划直接调用 `V5_final/scripts/ai_path_planning_v5.py` 中的 `astar_search`；未知格和硬阻断格不可通行，采用八邻接和防切角规则。合成“既有线路”图层只供仿真观察，完全排除在路线代价之外，不给路径提供线路先验。
4. 每次扫描前，服务端基于候选足迹的信息增益、无人机航程、任务走廊进展和未观测起终点优先级选点。首次连通路线生成前沿起点到终点的走廊选点；路线生成后改用当前 V5 路线折线引导探测。浏览器不能提交自制观测矩阵或代价场来影响规划结果。
5. 覆盖率每增加 20% 就用服务端累计观测调用 V5 A* 重规划；端点修改保留已采集数据和剩余扫描点，移动到未观测格的端点必须先被扫描才可用于规划。
6. 无人机在扫描中心之间按可调速度连续插值移动，青色轨迹标出已飞航段；浏览器每推进约 4.5 格就提交一批已飞子航段，服务端仍按不超过 1.5 格的间距采样，再刷新迷雾、覆盖率和观测图层。暂停会冻结插值进度，恢复后从当前位置继续。更换地图会使旧飞行请求失效。
7. 地图可从全图视图放大到 3 倍；放大后可用触屏、滚轮或滚动条查看局部，窗口尺寸变化时尽量保留视口中心对应的地形位置，点击和键盘选点仍对应原始网格坐标。画布焦点下方向键移动坐标光标；地图放大时视口焦点下方向键滚动地图。

仿真默认尺寸和扫描足迹反映的是 50 米网格下的区域扫描流程。该页面只有任务起点和终点，不载入中间电塔站点；电塔到电塔的任务仍由独立站点 CSV 规划输入处理。合成地形网格加密用于提高模拟空间采样细度，不等同于真实 DEM 的测绘精度。

主动扫描同时考虑扫描增益、航程、航向变化和任务进度。未发现可行路线前，使用以下主评分：

```text
score(c) = weighted_gain / (1 + 1.5 × distance + turn_penalty)
turn_penalty = 1.5 × (1 - cos(previous_heading, candidate_heading))
```

`weighted_gain` 是新观测格数、任务走廊进度收益和未观测起终点奖励之和；`guidance_weight` 随覆盖率从 0.75 增至 2.0。获得可行路线后，选点器优先沿局部 S 型扫描顺序推进，避免只追逐高增益而长距离折返。残余补扫会在地图上搜索能覆盖未知格的扫描中心，并优先靠近无人机的位置。

### 开源设计对照

[Fields2Cover](https://github.com/Fields2Cover/Fields2Cover) 将覆盖区域分解、扫描带生成、扫描带排序和可飞行路径连接拆成独立模块；其[路线规划文档](https://fields2cover.github.io/source/tutorials/route_planning.html)对已生成的扫描带优化访问顺序，其[目标函数文档](https://fields2cover.github.io/source/tutorials/objective_functions.html)分别衡量覆盖率、重叠、扫描带数量以及包含转弯的总距离。本模拟器借鉴“覆盖点生成与航段排序分层”和“转向计入航程”的设计，仍在未知地形上逐段获取传感器观测，因此不直接引入依赖已知多边形场地的 C++/OR-Tools 规划库。

## 正确性边界

- 规划器调用 V5 生产脚本的 A* 函数。在线规划的观测掩码和代价场由服务端会话维护；接口不接受客户端提供的观测矩阵。
- 代价与独立全图基准公式逐格对照，包含坡度、地形起伏、土地利用、道路和水域反向强度、由实体栅格计算的断裂带/铁路归一化距离代理、建筑、植被、保护区及五类灾害风险等因素；合成既有线路距离不进入路线代价公式。
- 路线只能经过已观测、可通行单元；对角线移动要求两侧相邻格也可通行。单元测试与 HTTP 流程测试覆盖未知端点、未知捷径、硬障碍和斜向切角。
- 噪声强度、精确分类观测和置信度公式是可解释的仿真设定，不代表真实载荷标定。合成数据和本地开源生成逻辑仅用于验证软件闭环，不能声称对掌握生成算法与种子的对手保密。
- 页面不是实测 DEM 或真实飞控。V5 的 CostUNet 虽训练于真实地理数据，本模拟器没有将其用于合成地形推断，也没有验证真实传感器精度、飞行安全或实地性能。
- 飞行插值用于呈现扫描中心之间的移动过程，不模拟加速度、续航、避障控制或通信延迟；航段采样用于模拟移动扫描覆盖，不能据此宣称真实载荷采样频率或飞行动力学性能。
- 搜索规模栏展示输出路线节点数；V5 A* 当前接口不返回扩展节点数，因此不把路线长度伪报成搜索扩展量。

## 启动

V5 模块导入需要项目 Python 环境中的 NumPy 和 Matplotlib。若存在 `D:\python\python.exe`，`start.bat` 会优先使用它；否则使用 `python`。安装依赖时使用与启动器相同的解释器：优先环境运行 `D:\python\python.exe -m pip install numpy matplotlib`，备用环境运行 `python -m pip install numpy matplotlib`。健康接口会报告规划依赖状态；缺少依赖时仍可生成地图和执行扫描，但路径规划会被禁用。

```powershell
cd D:\大创\V5_final\simulation
python server.py
```

打开 `http://127.0.0.1:8765`。Windows 也可以双击 `start.bat`。

若默认端口被占用，可指定其他端口启动：`python server.py --port 8766`，或在 PowerShell 运行 `.\start.bat --port 8766`；随后打开 `http://127.0.0.1:8766`。

## 真实 DEM 站间规划

主仿真页仍使用合成地形、网格坐标和已扫描代价场；其中的 `/api/plan` 只规划仿真网格。`/route-planner` 是单独的真实地理路线页面，使用 EPSG:4326 站点坐标和服务器上的 V5.0 DEM 规划器，不共享合成地图的坐标或代价输入。主页面顶部保留“真实站间规划”入口；真实规划页可在地图上分别点选起点和终点。服务必须配置台湾县市陆域 GeoJSON；服务端会同时检查端点是否被陆域多边形覆盖，并在返回成功前检查完整 `LineString` 是否仍被多边形覆盖。路线还需通过 DEM 有效像元检查，成功后将 `final_route.geojson` 叠加到地图上。缺少或无法读取陆域边界时，真实规划保持未就绪。县市行政边界不等同于测绘海岸线。模拟地图仍用于无人机扫描流程演示，不会替代真实 DEM 路线规划。

真实规划接口默认关闭。仅当服务进程配置了位于 `/data1/B24041626/pp` 内的源码、DEM 和任务输出路径时启用；浏览器不能提交文件路径，服务不会把真实路线计算回退到本机。服务器运行时可按部署目录设置：

```bash
python server.py --host 127.0.0.1 --port 8765
```

`TRANSMISSION_PLANNER_ROOT` 需直接包含 `transmission_path_planner/`；`TRANSMISSION_PLANNER_PYTHON` 指向已安装 V5.0 依赖的服务器虚拟环境解释器。`TRANSMISSION_PLANNER_LAND_MASK_GEOJSON` 是必填项，使用 WGS84 县市陆域 `Polygon`/`MultiPolygon` 文件。当前只接受已核验的内政部 1140318 县市界文件（SHA-256：`7e3d24cb13b7f1125c1c967d9d436ee556567516b0eb9894cfa3e763fe8874dd`），并要求陆域与 DEM 范围有正面积重叠，且至少一个有效 DEM 像元中心位于陆域内；缺少、哈希不符或无效时服务保持未就绪。更新边界版本时需审查来源与覆盖后同步更新指纹。当前验证依据县市行政边界，不应解释成精确海岸线。真实规划还必须配置至少 32 字符的随机访问口令；浏览器只在当前页面内存中提交口令，不写入任务文件。其他可选环境图层由 `TRANSMISSION_PLANNER_OSM_CACHE_DIR`、`TRANSMISSION_PLANNER_CONSTRAINT_GEOJSON`、`TRANSMISSION_PLANNER_OFFICIAL_HAZARDS_DIR`、`TRANSMISSION_PLANNER_POPULATION_RASTER` 指定，路径必须位于 `/data1/B24041626/pp`。应用固定使用官方灾害权重 1.0、OSM 建成区权重 2.0、脊线权重 0.1、地形坡度权重 0.75、粗糙度权重 0.25、相邻地面坡度权重 1.0（超过 30% 后仍线性增长）、A* 启发权重 1.0；启用人口栅格时使用权重 1.0 和保守的 `maximum` NoData 策略。任务仅运行 CPU 规划，不加载参考线路。接口一次只运行一个真实 DEM 任务，默认最长运行 3600 秒；路线 GeoJSON、DEM 地形预览、沿线高程剖面和溯源文件均写到唯一任务目录。用户需经 SSH 端口转发访问服务器回环地址；不要把服务绑定到公网接口。

页面默认按探索性未核验端点规划；它会使用 `--allow-unverified-endpoints` 并在结果中标注代理端点。切换到“已核验线路接入点”时，页面记录用户声明的来源与凭证引用，但程序不会替用户核验。输出 `planning_status`、硬约束状态或进程完成都不代表工程可行；当前规划器也不会按电压等级校核塔型、导线、档距、弧垂和净空。OpenStreetMap 浏览底图不参与代价计算，参考线路几何不会发送给规划器。

## API

- `GET /api/health`：返回服务状态、规划器名称、服务实例编号、`api_protocol` 和 `planner_ready`。依赖缺失时 `planner_ready` 为 `false` 并附带 `planner_error`，服务仍在线，地图生成与扫描仍可用；页面会禁用规划操作。携带会话编号时，还会返回轻量的 `snapshot_revision`，只读页面据此判断是否需要拉取完整地图快照。页面要求协议标识为 `server-authorized-scan-v4`；旧进程会被识别为版本不兼容并要求重启。只有带有效 `X-Page-ID` 的会话所有者才能续期地图会话；无页面编号的健康检查只读。`X-Control-Token` 仅续期同一页面当前持有的扫描控制租约，不会自动夺取控制权。
- `POST /api/session/control`：使用 `action: "acquire"` 并提交该页的 `release_token`，原子取得或续期控制权；响应包含观测格、任务端点、无人机位置和路线的完整快照及 fencing epoch 令牌。同页在控制响应丢失时可凭该凭证重新绑定当前租约。使用 `action: "release"` 释放匹配的控制租约。其他有效页面的写请求返回 HTTP 409；控制租约 30 秒未续期后可接管。
- `POST /api/session/release`：页面离开且未进入 BFCache 时，使用仅属于当前页面的释放凭证和页面实例编号尽力释放会话引用；若该页仍持有控制权，释放凭证会同时撤销该页的控制租约。复制页重放同一个地图请求时会登记独立引用和释放凭证。每个新文档使用独立页面编号；每个地图会话最多登记 32 个页面凭证，过期凭证会在容量满时淘汰。浏览器不一定会发送离开事件；漏掉释放通知的引用会留在会话中，其他页面停止续期后最迟 90 秒随会话过期，因此可能暂时占用地图槽位。
- `POST /api/world`：用 `seed`、`width`、`height` 创建地图会话，必须包含 `page_id` 以登记当前文档实例；可选 `request_id` 用于安全重试，`replace_session_id` 用于尝试替换本页面的旧会话。响应包含公开任务元数据、仅用于释放的随机凭证、服务实例编号和协议标识，不包含真实地形图层或实际地形种子。重放请求可以让多个页面登记为同一会话的独立所有者。服务端会先检查会话容量再生成地形；容量暂满时，页面对明确的容量错误最多短退避重试 3 次，并复用同一请求编号。
- `POST /api/mission/points`：用 `session_id`、`start`、`goal` 设置本会话的任务端点；可选 `keep_leg_id` 仅用于保留当前飞行或待确认扫描仍依赖的匹配航段授权，未开始的旧选点授权会失效。首次扫描前修改起点会同步无人机初始位置；飞行过程中无人机位置仍由服务端维护。
- `POST /api/scan/next`：请求体包含 `session_id`、以网格为单位的扫描 `radius`（页面默认 4 格，即 200 米），以及可选 `guidance_weight`。候选点、无人机位置和任务端点均由服务端状态决定；响应包含服务端确认的无人机位置，以及下一目标点和航段授权 `leg_id`（无目标时 `target` 为 `null`，仍须返回无人机位置）。
- `POST /api/scan/path`：请求体包含 `session_id`、航段 `start`/`end`、与授权半径一致的 `radius`、服务端签发的 `leg_id` 和唯一 `request_id`。服务端验证控制令牌和授权航段后，沿已飞路径按固定间距采样并返回融合后的观测数据和累计确认航程；同一已提交请求重放不会重复采样或重复计距。每张地图保留最多 8192 个请求编号收据以限制内存增长；达到上限后，新扫描请求会被拒绝，需重新生成地图。超过 32 条的旧请求响应被淘汰后仍可识别为已提交，客户端读取完整快照恢复数据。
- `POST /api/session/scan-state`：仅读取已提交的观测、任务、无人机位置、路线、累计确认航程和 `snapshot_revision`，不续期地图会话。
- `POST /api/scan/measure`：已关闭，返回 `410 Gone`；扫描只能通过 `/api/scan/next` 获取授权后调用 `/api/scan/path`。
- `POST /api/plan`：请求体包含 `session_id`、`start` 和 `goal`；服务端使用累计观测调用 V5 A*，未知格和硬阻断格不可通行。
- `POST /api/routes/validate-point`：携带 `X-Planner-Token` 和 EPSG:4326 的 `lat`、`lon`，只读检查所选点是否落在当前台湾 DEM 有效像元和台湾县市陆域多边形内；不会创建规划任务或写入输出文件。
- `POST /api/routes`：携带 `X-Planner-Token`，在服务器端提交真实 DEM 站间规划任务；路线计算和结果写入仅发生在服务器配置的 `/data1/B24041626/pp` 目录。服务端在任务标记成功前检查端点和完整 GeoJSON 路线是否被台湾县市陆域多边形覆盖，并验证路线落在 DEM 有效像元内；任何一项失败都不会将任务标记为成功。

会话保存在进程内存，最多保留最近 4 张地图；服务重启会清除会话。该设置面向本地演示，不是多用户持久化部署方案。
